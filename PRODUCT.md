# 1. Что это за продукт

«Старший брат» — интерактивный справочник и навигатор по участникам одноимённого Telegram-сообщества.

Продукт преобразует экспорт темы с визитками участников в структурированную базу, в которой можно:

- быстро найти нужного человека;
- понять, чем он занимается;
- понять, чем он может быть полезен;
- найти человека по конкретной задаче;
- найти людей с похожими жизненными или бизнес-вызовами;
- выбрать себя и получить персональную подборку участников;
- сохранить интересных людей в «Мои братья»;
- открыть полную визитку;
- скопировать Telegram-имя или перейти в Telegram напрямую, когда настоящий `@username` присутствует в исходных данных.

Это НЕ социальная сеть.  
Это НЕ отдельный мессенджер.  
Это НЕ CRM.  
Это НЕ платформа с личными кабинетами.  
Это НЕ новая база данных, которую участники должны заполнять вручную.

Основой продукта является уже существующая информация из Telegram-визиток.

---

# 2. Основная проблема

В Telegram-сообществе может находиться 200–300+ участников. У каждого есть опыт, компетенции, бизнес, профессия, проблемы, цели и сферы, в которых он может быть полезен.

Но Telegram практически не позволяет использовать эту информацию как структурированную базу. Чтобы найти человека, который разбирается в продажах, работает в производстве, занимается AI, прошёл через кассовый разрыв, переживает развод, умеет привлекать клиентов, может помочь с CRM, занимается строительством или находится в аналогичной жизненной ситуации, пользователю приходится вручную перечитывать сотни сообщений.

Практическая ценность сообщества оказывается скрыта внутри неструктурированного текста.

---

# 3. Продуктовая гипотеза

Если превратить визитки участников в структурированный и хорошо спроектированный интерактивный справочник, пользователь сможет за несколько секунд найти людей, которые релевантны его текущей задаче.

Основная ценность продукта:

> Не просто показать, кто находится в сообществе, а помочь понять, с кем именно тебе стоит познакомиться.

---

# 4. Основной обещаемый результат

Пользователь должен открыть «Старший брат» и за 5–15 секунд понять:

1. Что здесь можно сделать.
2. Как найти нужного человека.
3. Как найти человека, который может помочь.
4. Как найти людей с похожей ситуацией.
5. Как получить рекомендации именно для себя.
6. Как связаться с найденным участником через Telegram.

# 6. Источник данных

Главным источником является HTML-экспорт Telegram темы с визитками участников.

Базовый сценарий:

Telegram Desktop  
→ группа «Старший брат»  
→ тема «Визитка - представление»  
→ меню  
→ экспорт истории  
→ HTML  
→ `messages.html`

Приложение локально разбирает файл и формирует структурированную базу.

---

# 7. Критическое правило данных

Приложение НЕ ИМЕЕТ ПРАВА придумывать информацию об участниках.

Допустимые источники:

1. текст визитки;
2. Telegram display name автора;
3. реальный `@username`, если он действительно присутствует в экспорте и его можно уверенно привязать к автору;
4. изображения, если они действительно входят в экспорт и могут быть уверенно связаны с визиткой;
5. вычисляемые теги и классификации на основе текста;
6. пользовательские настройки внутри приложения: избранное, выбранный пользователь, выбранные интересы, выбранные задачи.

Запрещено придумывать:

- должность;
- город;
- компанию;
- фотографию реального человека;
- Telegram username;
- рейтинг;
- количество знакомств;
- сообщения;
- события;
- активности;
- статус online;
- личный кабинет;
- несуществующие достижения;
- несуществующие связи между людьми.

# 8. Структура визитки

Типовая анкета содержит:

1. Имя.
2. Город.
3. Возраст.
4. Чем занимается.
5. Что сейчас самое тяжёлое.
6. Что сейчас самое важное.
7. Каким результатом будет гордиться через 90 дней.
8. Чем может быть полезен другим участникам.

Парсер НЕ должен считать нумерацию абсолютно надёжной. Реальные пользователи могут нарушать номера, объединять пункты, пропускать пункты, повторять номера, писать свободным текстом и вставлять дополнительные абзацы.

# 10. Аватары

Telegram HTML-экспорт не гарантирует наличие реального profile photo каждого участника.

Система поддерживает три уровня:

### Уровень 1 — реальное изображение
Используется только когда оно действительно существует и однозначно принадлежит человеку.

### Уровень 2 — изображение из визитки
Если пользователь прикрепил изображение к своей визитке и его можно уверенно связать с автором, его можно использовать в карточке.

### Уровень 3 — брендовый fallback
Для каждого человека генерируется стабильный декоративный avatar:

- инициалы;
- фирменная эстетика «Старшего брата»;
- графит / чёрный / тёплое золото;
- вариативная композиция;
- avatar детерминирован именем человека.

Такой avatar не должен выглядеть как фотография реального человека.

# 11. Telegram-контакт

После нахождения интересного человека пользователь должен максимально быстро перейти к контакту.

## Сценарий A — username известен

Показывать:

- **Открыть в Telegram** → `https://t.me/username`
- **Скопировать @username**

## Сценарий B — username неизвестен

Показывать:

- **Скопировать имя**

Копируется Telegram display name. Нельзя создавать Telegram URL только по display name.

# 12. Основные пользовательские сценарии

## 12.1 Найти конкретного человека

Пользователь вводит `Леонид Цветков` и получает точное совпадение.

## 12.2 Найти специалиста

Пример запроса: `кто разбирается в продажах B2B`.

Поиск идёт по деятельности, полезности, тегам и тексту визитки.

## 12.3 Найти человека из определённой сферы

Например `IT / AI` → участники из этой сферы.

## 12.4 Найти человека с похожей проблемой

Например `Поиск клиентов` или `Долги / финансы` → люди с похожим вызовом.

## 12.5 Выбрать себя

Пользователь находит собственную визитку. После выбора приложение знает его исходный профессиональный и жизненный контекст.

## 12.6 Дополнить свои интересы

Пользователь отмечает, например:

- Производство;
- Продажи;
- CRM;
- Автоматизация;
- Строительство;
- Финансы.

## 12.7 Указать текущую задачу

Например:

- Поиск клиентов;
- Масштабирование;
- Автоматизация;
- Финансы;
- Поиск партнёров.

## 12.8 Получить персональные рекомендации

На основании собственной визитки, деятельности, «чем может помочь», проблем, выбранных интересов и задач система строит блок **«Подобрано для тебя»**.

# 13. Персональный подбор

Рекомендательная система — одно из ключевых отличий продукта.

Она не должна быть случайной и не должна показывать фальшивые проценты вроде `98% match`, если модель этого не обосновывает.

Вместо этого использовать понятные статусы:

- Высокое совпадение;
- Подходит по интересам;
- Может помочь с задачей;
- Похожий вызов;
- Смежная сфера.

Обязательно показывать блок **«Почему в подборе»**.

Пример:

> Работает с автоматизацией и CRM. В визитке указал опыт B2B и внедрения бизнес-систем.

---

# 14. Первая версия Recommendation Engine

Допустимо использовать взвешенный heuristic scoring.

Факторы:

```text
совпадение выбранной сферы
совпадение профессиональных тегов
can_help_with совпадает с задачей пользователя
общий challenge
совпадение значимых ключевых слов
город
пересечение целей
```

Итог пользователю показывается не числом, а понятным объяснением.

---

# 15. Будущий AI-уровень

Следующий этап — embeddings / semantic search.

Пример запроса:

> Мне нужен человек, который поможет выстроить продажи производственной компании.

Система должна находить релевантные визитки даже без буквального совпадения слов.

AI не создаёт новые факты. Он только сопоставляет существующие тексты.

# 21. Блок «Подобрано для тебя»

На desktop располагается справа от блока выбора себя.

Формат: 4 компактные карточки в одну строку.

Каждая карточка:

- имя;
- основная профессиональная сфера;
- город;
- 1–2 причины рекомендации;

Карточка:

# 35. Хранение

Полную базу участников нельзя хранить в `localStorage`.

### IndexedDB хранит:

- profiles;
- source data;
- index;
- parsed metadata.

### localStorage хранит только:

- selectedSelfId;
- favorites;
- UI preferences;
- selected interests;
- selected challenges;
- onboarding status.

# 45. Motion-правила

Button press:

```css
transform: scale(.97)
```

Duration:

- button press: 100–160 ms;
- small popover: 125–200 ms;
- dropdown: 150–250 ms;
- drawer / modal: 200–300 ms.

Custom easing:

```css
--ease-out: cubic-bezier(.23, 1, .32, 1);
--ease-in-out: cubic-bezier(.77, 0, .175, 1);
--ease-drawer: cubic-bezier(.32, .72, 0, 1);
```

Нельзя использовать:

```css
transition: all
```

---

# 46. Hover

Hover только на устройствах:

```css
@media (hover:hover) and (pointer:fine)
```

Карточка:

- небольшое усиление shadow;
- максимум 1–2 px visual lift;
- без прыжков интерфейса.

---

# 47. Accessibility

Поддерживать:

```css
prefers-reduced-motion
```

Touch targets — минимум приблизительно 44 px.

# 48. Performance

После загрузки базы:

- поиск должен работать мгновенно;
- не рендерить одновременно 250 тяжёлых карточек;
- использовать pagination / incremental render;
- 20–30 карточек первой загрузки;
- следующая партия по запросу / scroll.

# 49. Error handling

Импорт не должен падать browser alert вида:

`QuotaExceededError`

или:

`Failed to execute setItem`

Ошибки показываются нормальным UI-state.

# 50. Продуктовые принципы

1. **Польза раньше статистики.**
2. **Действие раньше анализа.**
3. **Реальные данные раньше красивых цифр.**
4. **Один клик до результата.**
5. **Ничего не придумывать за сообщество.**

Примеры:

- Сфера → люди.
- Проблема → люди.
- Мои братья → сохранённые.
- Рекомендация → анкета.

Версия не считается готовой только потому, что HTML открывается, дизайн выглядит красиво или импорт сработал один раз.

### Desktop 1440 px

Проверить:

- загрузку;
- главную;
- поиск;
- выбор себя;
- recommendation;
- сферы;
- challenge;
- favorite;
- profile;
- copy;
- повторный import.

### Mobile 390 px

Проверить те же сценарии.

Технические требования:

- JS errors = 0;
- horizontal overflow = 0;
- quota error = 0;
- console critical errors = 0;
- broken interactions = 0.

# 59. Финальная формулировка продукта

«Старший брат» превращает Telegram-визитки участников в интерактивную карту сообщества.

Пользователь может найти человека по профессии, компетенции, задаче или похожей жизненной ситуации, выбрать себя и получить персональную подборку людей, сохранить интересных участников и быстро перейти к знакомству в Telegram.

Основная ценность продукта:

**сделать скрытый опыт сообщества доступным и практически применимым.**
