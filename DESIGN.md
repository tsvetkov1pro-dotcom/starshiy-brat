# DESIGN.md — СТАРШИЙ БРАТ

Статус: **CANONICAL / LOCKED V1**  
Назначение: единственный источник истины по визуальной системе продукта.

`PRODUCT.md` определяет, **что существует** в продукте.  
`DESIGN.md` определяет, **как существующее выглядит и ведёт себя визуально**.  
`ARCHITECTURE.md` определяет, **как это реализовано технически**.

Если новая UI-идея конфликтует с этим документом, действует `DESIGN.md`, пока пользователь явно не согласовал изменение.

## 1. Канонический референс

Главный desktop-экран V1 утверждён пользователем 04.09.2026.

Референс хранится в репозитории:

`docs/design/reference-home-v1.svg`

Это визуальный source of truth для композиции главной.

Дополнительные пользовательские уточнения к референсу:

- строка поиска должна быть **слегка шире**, чем на исходном референсе;
- вертикальные расстояния между крупными блоками должны быть **немного увеличены** — ориентир +4 px к базовому ритму;
- конструкция, состав блоков, типографика, палитра, иконография, fallback-аватары, графика сфер и hover-поведение считаются утверждёнными.

## 2. Базовый визуальный принцип

Интерфейс продукта — светлый, спокойный и функциональный.

Брендовый слой — тёмный cinematic urban: поздний вечер, дворы и многоэтажки, тёплый закат, графитовый/чёрный автомобиль, взрослый мужчина и ребёнок, золото/янтарь, фактурная типографика «Старший Брат».

Комбинация:

**light product UI + dark cinematic brand graphics + warm gold accent**.

Запрещено самовольно вводить:

- generic purple SaaS;
- кислотные цвета;
- тёмную тему всего приложения;
- декоративный glassmorphism;
- случайные AI-иллюстрации другого стиля;
- декоративные графики без продуктовой функции;
- новые сущности только ради визуальной плотности.

## 3. Что существует на главной

Порядок desktop-композиции зафиксирован:

1. Sidebar.
2. Компактный cinematic hero.
3. Search bridge, частично перекрывающий нижнюю границу hero.
4. Верхний рабочий ряд:
   - слева `Выберите себя`;
   - справа `Подобрано для тебя` — максимум 4 карточки в первом экране.
5. `Мои братья` — компактная горизонтальная полоса.
6. Нижний ряд:
   - слева `Сферы сообщества`;
   - справа `Кто проходит через похожие вызовы`.
7. `Импорт чата` остаётся в нижней части sidebar.

Главная не должна превращаться в социальную сеть, портал с лентой или личный кабинет.

## 6. Layout desktop

Целевой reference viewport: **1440–1450 px**.

Основные правила:

- sidebar: около `220–230 px`;
- content column: `minmax(0, 1fr)`;
- рабочая область не должна иметь horizontal overflow;
- общий max-width контента: около `1180–1220 px` после sidebar;
- внутренний horizontal padding контента: `22–28 px`;
- vertical section gap: `18 px` как базовый ритм крупного уровня;
- card gap: `10–14 px`;
- outer radii: спокойные, без чрезмерно круглых SaaS-контейнеров.

Главный экран должен помещать hero, верхний рабочий ряд, `Мои братья` и начало нижнего ряда без ощущения огромного пустого пространства.

---

## 7. Hero

Hero — брендовый, но **не доминирующий по высоте**.

Desktop:

- ориентир высоты: `220–250 px`;
- width: 100% рабочей области;
- radius: `18–22 px`;
- artwork: `public/brand/hero-v1.svg`;
- `object-fit: cover` / `background-size: cover`;
- не растягивать hero до 300–400+ px;
- search bridge перекрывает нижнюю кромку hero.

Hero-графика уже содержит согласованный брендовый narrative. Не рисовать вместо неё абстрактные CSS-солнца, дома, силуэты или псевдофотографию.

Mobile может использовать более плотный crop того же art-direction или исходный community avatar, но не другой визуальный стиль.

---

## 8. Search bridge

Search — один из главных элементов конструкции.

Desktop:

- расположен поверх нижней части hero;
- центрирован;
- шире канонического референса примерно на `60–100 px`;
- целевой max-width: около `840 px`;
- height: около `50–56 px`;
- background: почти белый;
- border: тонкий тёпло-серый;
- shadow: мягкий, небольшой;
- radius: `13–15 px`;
- слева search icon;
- placeholder: `Кого ищешь? Например: IT, продажи, стройка…`;
- справа существующее действие поиска, если оно не ухудшает плотность desktop-композиции.

Focus state — тонкое золотое/графитовое усиление бордера, без neon glow.

## 10. Fallback-аватары участников

Это LOCKED-система.

Assets:

- `public/brand/avatars/avatar-01.svg`
- `public/brand/avatars/avatar-02.svg`
- `public/brand/avatars/avatar-03.svg`
- `public/brand/avatars/avatar-04.svg`
- `public/brand/avatars/avatar-05.svg`
- `public/brand/avatars/avatar-06.svg`

Правила:

- все fallback-аватары происходят из одного утверждённого cinematic/grunge набора;
- для каждого profile ID выбирается один вариант через deterministic hash;
- визуально набор выглядит «вразнобой», но avatar конкретного участника не прыгает при rerender/reload;
- не генерировать инициалы поверх серых кругов;
- не использовать реалистичную фотографию, будто это настоящий участник;
- если появится реальная photo attachment, корректно связанная с участником, она имеет приоритет над fallback.

## 11. Карточка участника

Desktop recommendation card — компактная.

Содержимое:

- avatar;
- имя;
- короткая сфера/деятельность;
- при наличии — возраст или город в одной вторичной строке;
- иконка favorite/copy только если она соответствует реальной функции;
- открытие анкеты.

Карточка не должна содержать выдуманных подписчиков, статусов online, сообщений или активности.

Hover:

- border становится немного теплее;
- карточка поднимается максимум на `1–2 px`;
- shadow слегка усиливается;
- transition `160–220 ms` ease-out.

Press:

`transform: scale(.97)` на интерактивной кнопке/карточке, где это не ломает layout.

## 13. Сферы сообщества

Это LOCKED graphic family.

Assets:

- `public/brand/spheres/it-ai.svg`
- `public/brand/spheres/construction.svg`
- `public/brand/spheres/finance.svg`
- `public/brand/spheres/sales.svg`
- `public/brand/spheres/marketing.svg`
- `public/brand/spheres/production.svg`

Графика:

- IT / AI — золотая circuit/brain line-art на чёрном;
- Строительство — crane/building illustration на тёплом светлом фоне;
- Финансы — золотой rising bars/arrow на чёрном;
- Продажи — target/arrow на светлом grunge;
- Маркетинг — megaphone на светлом grunge;
- Производство — gears на чёрном/графитовом.

Количество участников всегда вычисляется из реальных данных. Никакие числа из референса не хардкодить.

Tile hover:

- лёгкий `translateY(-2px)`;
- gold border / inner outline;
- стрелка или affordance чуть смещается вправо;
- никаких 3D-поворотов и тяжёлых parallax-эффектов.

`IT / AI` не должен визуально быть отдельной дизайн-системой: размеры, radius, подписи и hover совпадают с остальными tiles.

## 16. Типографика

Интерфейсная типографика остаётся нейтральной и компактной.

Основной стек:

`Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`

Принципы:

- UI body: `13–15 px`;
- section title: `18–20 px`, semibold/bold;
- card title: `13–15 px`, semibold;
- metadata: `11–13 px`;
- hero typography может быть baked into approved artwork;
- не смешивать serif/editorial type с текущей системой без согласования.

---

## 17. Иконография

Текущая line icon family зафиксирована.

- stroke: примерно `1.7–1.9`;
- sidebar: `18–20 px`;
- inline actions: `14–18 px`;
- не смешивать outline icons с случайными filled emoji/icon packs.

---

## 18. Motion / Emil Kowalski rules

Используем правила официального Emil Kowalski design engineering skill.

Tokens:

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
```

Правила:

- не использовать `transition: all`;
- hover только при `@media (hover:hover) and (pointer:fine)`;
- button press ориентир `100–160 ms`;
- UI hover/microinteraction обычно `160–220 ms`;
- drawer/modal `200–300 ms`;
- enter/exit — ease-out;
- movement внутри экрана — ease-in-out;
- modal не должен «летать» из случайной точки;
- `prefers-reduced-motion` обязателен.

## 20. UI review текущей миграции

| Before | After | Why |
|---|---|---|
| CSS-абстракция вместо фото в hero | Утверждённый cinematic artwork | Бренд должен быть узнаваемым и совпадать с аватаркой сообщества |
| Серые/инициальные fallback avatars | 6 утверждённых cinematic/grunge avatars | Живой единый визуальный язык сообщества |
| Декоративный treemap без утверждённой графики | 6 согласованных category artworks | Сферы становятся частью бренда, а не generic dashboard |

| Search уже референса | max-width около 840 px | Пользователь явно запросил слегка расширить строку поиска |

## 21. Change protocol

Любое визуальное изменение проходит цепочку:

**Requirement → Reference → Implementation → Visual QA → Functional QA → Approval → LOCKED**.

Правила для следующих чатов/Codex/агентов:

1. Перед UI-работой прочитать `PRODUCT.md` и `DESIGN.md`.
2. Найти затрагиваемый элемент в разделе `LOCKED`.
3. Если элемент LOCKED и пользователь не просил его менять — оставить его без редизайна.
4. Не копировать функции из визуальных референсов, если их нет в `PRODUCT.md`.
5. Не говорить «готово» до фактической сборки и визуальной/функциональной проверки.
